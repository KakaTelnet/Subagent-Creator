## 4. 场景准备

### A. 主链路项目

准备无外部依赖的小型 JavaScript 项目，包含两个模块、现有内置测试及少量 `.txt` 数据：

- 源码提供“标签规范化”和“去重后排序”两个调用路径；当前实现及现有测试均通过。
- 业务目标：在现有字符串数组输入范围内，新增“忽略仅由空白组成的项”的行为，保留既有排序和大小写规则；空数组结果仍为空数组。
- 团队事实：项目会反复进行只读调用链定位；这类探索需要独立上下文，并与代码修改职责分开。现有工程约束要求独立核验修改结果。
- 事实文档放在目标根 `ai_docs/notes/YYYYMMDD-HHMM_项目事实.md`；根 `AGENTS.md` 是所需配置入口，可创建。无需正式 PRD 模板。
- 准备一个名称不冲突、原生格式有效的用户自有 Agent、一个有效的无关 config 设置和一段用户指令原文作为保护哨兵；哨兵不带生成器所有权标记。保存原始字节与哈希。

角色名称由 Skill 决定。上述事实通常足以支持只读探索/核验与可写实现的区分；若生成器合并，须按独立职责理由判定是否合理，不能仅按角色数量评分。业务任务和测试断言应在调用前冻结，执行中不通过删减断言来“通过”。

### B. 边界项目

复用 `tooling/tests/fixtures/forward_cases.json` 中的 5 个场景 ID、`agent_input` 和 `oracle`。主链路覆盖 CREATE、UPDATE；另建隔离副本覆盖 EXPLAIN、无团队必要性、AUDIT。AUDIT 副本需要协调者预置一个有效但职责重复的受管角色，先确认结构验证通过，再测是否提出可恢复退役建议。

现有 `representative_team` 使用占位模型，只可参考布局或用于静态测试，不能直接作为真实创建成功的证据。CREATE 必须从没有受管团队的目标出发，由被测 Skill 生成文件。

## 7. 什么算真实调用

- 必须有宿主事件证明选择了生成的原生自定义角色，关联角色配置和 child/session ID；随后有该子 Agent 的真实工具行为与结果。
- 普通临时 Agent、主 Agent 自行完成任务、把角色 prompt 复制给通用 Agent，均不满足 E2/E3。
- 自报模型/权限和 TOML 字段仅是声明；真实模型、有效权限和实际宿主版本需记录可追溯的宿主来源。字段不可观测时记 UNVERIFIED，相关必需项 BLOCKED。
- 不从“没有写文件”推断操作系统只读。若有效权限与配置不符，保留差异，判断是父会话覆盖还是配置失效；E4 不通过，不能静默调整期望值。
- 不实施越权写入探测。本轮使用只读工具轨迹、宿主权限元数据与哈希对照；缺少元数据不能补造。
- 当前 Python API 的 `HostModelEvidence`、`HostPermissionEvidence`、`HostCodexVersionEvidence` 必须来自真实可信宿主集成。仅把人工拼出的字符串装进 typed 对象，不能增加可信度。
- 本方案结果与验证器的 `AGENT_TEAM_*` 状态分开保存。若实际调用证据足够满足 E0–E8，但没有可用的可信 Python API 集成，可记录本方案 PASS，并保持验证器实际返回的 CONFIGURATION_READY；不得伪造 RUNTIME_READY/VERIFIED。若连原始宿主证据也缺失，则本方案 BLOCKED。

报告与状态索引使用以下可检索标记（只是文档状态，不新增程序 Schema）：

```text

```

状态判定：

| 标记 | 条件 |
| --- | --- |
| NOT_RUN | 尚未开始实际验收；方案编写和先前单元测试不改变该状态 |
| RUNNING | 执行已开始且存在本次报告 |
| PASS | E0–E8 全部通过，真实角色调用与必要宿主证据齐全，无未关闭必需项 |
| FAIL | 已观测到至少一个必需验收行为违反契约；即使另有阻断，总结果仍 FAIL |
| BLOCKED | 尚未观测行为失败，但因版本、账户、工具、权限或证据缺口无法完成必需项 |

每个步骤还可保持 NOT_RUN；总体不允许“部分 PASS”。出现失败或阻断后，继续完成不依赖该缺口的检查，依赖步骤保持未执行。

PASS 仅对报告记录的源码、宿主和模型配置有效。后续这些因素变化，状态索引保留历史 PASS，但“适用于当前版本”改为“待复验”，不得沿用旧标记宣称新版本通过。不自动创建 Git tag、commit、release 或 push。
